# План разработки приложения «DebtTrack» (тема «Долги»)
### Android Studio · Kotlin · Room · MVVM · 14 недель

Основан на предоставленных макетах экранов (Главная, Новый долг, Детали долга,
Добавить платёж, Статистика, Настройки) и ТЗ по МДК 01.03.

---

## 0. Общая архитектура проекта

**Технологии:**
- Kotlin, Android Studio
- Room (SQLite) — база данных
- MVVM: ViewModel + LiveData/StateFlow
- Navigation Component + BottomNavigationView (Главная / Статистика / Настройки, как на макете)
- MPAndroidChart — круговая диаграмма на экране «Статистика»
- WorkManager — фоновые напоминания о сроках (изюминка проекта)
- DataStore/SharedPreferences — настройки (тема, сортировка, уведомления)
- View/DataBinding — для форм и списков

**Структура пакетов:**
```
com.example.debttrack/
 ├─ data/
 │   ├─ database/        (AppDatabase, DAO)
 │   ├─ entities/         (Debt, Category, Payment, Tag, DebtTagCrossRef)
 │   └─ repository/       (DebtRepository, PaymentRepository, ...)
 ├─ ui/
 │   ├─ home/             (главный экран, список долгов)
 │   ├─ debtform/         (новый долг / редактирование)
 │   ├─ debtdetail/       (детали долга)
 │   ├─ payment/          (добавить платёж)
 │   ├─ statistics/       (статистика)
 │   └─ settings/         (настройки)
 ├─ viewmodels/
 ├─ adapters/
 ├─ notifications/        (WorkManager, NotificationHelper — изюминка)
 └─ utils/                (форматирование валюты, дат, валидация)
```

## 1. Схема базы данных (Room)

Минимум 3 основные таблицы + 1 промежуточная — по ТЗ. В проекте будет 5 таблиц:

| Таблица | Тип | Назначение |
|---|---|---|
| **Category** | основная | Категории долгов (Электроника, Путешествия, Автомобиль…) |
| **Debt** | основная | Сам долг: имя человека, сумма, тип (мне должны / я должен), срок возврата, категория (FK), статус |
| **Payment** | основная | История платежей по долгу (один-ко-многим: Debt → Payment) |
| **Tag** | доп. | Метки долга (например «Срочно», «Друзья», «Семья») |
| **DebtTagCrossRef** | **промежуточная** | Связь многие-ко-многим Debt ↔ Tag |

Связи:
- `Category (1) → Debt (N)` — один-ко-многим, FOREIGN KEY, `onDelete = CASCADE`
- `Debt (1) → Payment (N)` — один-ко-многим
- `Debt (N) ↔ Tag (N)` через `DebtTagCrossRef` — многие-ко-многим

## 2. План по неделям (14 пунктов)

Каждый пункт = отдельная ветка/этап работы → по завершении делается **коммит** с осмысленным сообщением в формате `git commit -m "..."` (сообщения предложены ниже). Рекомендуется в конце каждой недели делать `git push` и при необходимости `git tag`.

### Неделя 1 — Инициализация проекта и архитектура
- Создать проект в Android Studio (Kotlin, min SDK 24+)
- Настроить Git-репозиторий, `.gitignore`, базовый `README.md`
- Подключить зависимости: Room, Lifecycle (ViewModel/LiveData), Navigation, MPAndroidChart, WorkManager
- Создать структуру пакетов (data, ui, viewmodels, adapters, notifications, utils)
- Настроить тему приложения (цвета из макета: градиент синий/бирюзовый, стиль карточек)

**Коммит:** `Initial project setup: architecture, dependencies, README`

### Неделя 2 — Проектирование и реализация базы данных
- Создать Entity-классы: `Category`, `Debt`, `Payment`, `Tag`, `DebtTagCrossRef`
- Прописать внешние ключи и `onDelete = ForeignKey.CASCADE`
- Реализовать DAO для каждой таблицы (Insert/Update/Delete/Query)
- Создать `AppDatabase` (Room), настроить `Migration` при необходимости
- Добавить предзаполнение (prepopulate) тестовыми категориями

**Коммит:** `Add Room database: entities, DAOs and relations`

### Неделя 3 — Repository и базовая архитектура MVVM
- Реализовать `DebtRepository`, `PaymentRepository`, `CategoryRepository`
- Настроить работу с БД в фоновом потоке (Coroutines + Dispatchers.IO)
- Создать базовые `ViewModel` + `ViewModelFactory`
- Добавить утилиты: форматирование сумм в рублях (`12 500 ₽`), форматирование дат

**Коммит:** `Add repository layer and base MVVM architecture`

### Неделя 4 — Навигация и каркас экранов
- Настроить `BottomNavigationView` (Главная / Статистика / Настройки — как на макете)
- Настроить `Navigation Component` (граф навигации, переходы Главная → Детали долга → Добавить платёж)
- Создать заглушки всех 5 экранов
- Настроить toolbar/back-навигацию для вложенных экранов (Детали долга, Новый долг)

**Коммит:** `Add navigation architecture and screen placeholders`

### Неделя 5 — Главный экран (список долгов)
- RecyclerView + Adapter для списка долгов («Ближайшие платежи»)
- Карточки-сводки «Мне должны», «Я должен», «Чистый баланс»
- Прогресс-бар выполнения по каждому долгу, бейджи статуса (Активный/Частично)
- FAB для перехода на экран добавления долга
- Пустое состояние (empty state) при отсутствии долгов

**Коммит:** `Implement home screen: debt list, summary cards, empty state`

### Неделя 6 — Поиск, фильтрация и сортировка
- Текстовый поиск по имени должника/описанию (фильтр списка в реальном времени)
- Минимум 2 фильтра: по категории и по статусу/дате возврата
- Сортировка списка (по сроку возврата, по сумме, по имени) — согласовать с настройкой на экране «Настройки» («Сортировка долгов»)

**Коммит:** `Add search, filtering and sorting to home screen`

### Неделя 7 — Экран «Новый долг» (Создание)
- Форма: переключатель «Мне должны / Я должен», поле имени, сумма, срок возврата (DatePicker), категория (Spinner из таблицы Category), описание

### Неделя 8 — Экран «Детали долга» (Чтение/Удаление)

### Неделя 10 — Экран «Добавить платёж»

**Коммит:** `Implement payment screen and automatic debt status update`

### Неделя 11 — Экран «Статистика»
- Карточки: «Я должен», «Мне должны», «Просрочено»

**Коммит:** `Implement statistics screen with chart and aggregated analytics`

### Неделя 12 — Экран «Настройки»

**Коммит:** `Implement settings screen: theme, sorting and notification prefs`

### Неделя 13 — «Изюминка»: напоминания о сроках возврата
- `WorkManager` (периодический `Worker`), ежедневно проверяет долги с приближающимся сроком возврата

**Коммит:** `Implement due-date reminder notifications (unique feature)`

## 3. Как оформлять коммиты и репозиторий (пункт «GitHub» — 5 баллов)

- Коммитить **каждую неделю минимум 1 раз**, а лучше — несколько раз по мере выполнения подпунктов (например, отдельно DAO, отдельно UI списка)
- Формат сообщений: `<Действие>: <что сделано>` (см. примеры выше), на английском или русском — главное осмысленно, не «fix», «update», «asd»
- Использовать ветки: `feature/home-screen`, `feature/statistics`, `feature/notifications` и мержить в `main` через Pull Request (даже соло-проекту это добавит баллов за аккуратность)
- В конце — файл `README.md` с: описанием приложения, стеком технологий, схемой БД, инструкцией по запуску, скриншотами
